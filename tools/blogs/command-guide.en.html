3. File permissions, ownership and access management

This section covers the terminal commands used to manage user permissions and to control who can read or change files. Although the permission system differs between Windows, macOS and Linux, the basic idea is the same: read, write and execute permissions.

3.1. Users and Groups

ConceptDescriptionExample
UserThe person logged in to the systemwhoami → current user
GroupAn access group that users belong togroups → groups you belong to
OwnerThe person who created the fileFirst column in the ls -l output

3.2. Viewing Permissions

Commands for viewing permissions on Linux/macOS and Windows:

  • ls -l - Lists file permissions.
  • stat dosya.txt - Gives detailed information about a file.
  • icacls dosya.txt - Lists file permissions on Windows.
  • Get-Acl dosya.txt - Shows ACL details in PowerShell.
Tip: The -rwxr-xr-- format is a short summary of permissions on Linux. The first character is the type (- = file, d = directory), followed by the user, group and other permissions.

3.3. Changing File Permissions (chmod)

  • chmod izin dosya - Changes the permissions of a file or folder (chmod 755 script.sh).
  • icacls dosya /grant kullanıcı:F - Gives a user full control (Windows).

Numeric permission system (Linux/macOS):

DigitMeaningDescription
7rwxread + write + execute
6rw-read + write
5r-xread + execute
4r--read only

3.4. Ownership (chown) and Group Assignment (chgrp)

  • chown kullanıcı dosya - Changes the file owner (chown ali belge.txt).
  • chown kullanıcı:grup dosya - Changes the owner and group together.
  • chgrp grup dosya - Changes only the group.
  • icacls dosya /setowner kullanıcı - Sets the owner on Windows.

3.5. Read-only / Executable Files

GoalLinux/macOSWindowsDescription
Make a file read-onlychmod 444 dosya.txtattrib +R dosya.txtThe file can no longer be modified.
Add execute permission to a scriptchmod +x script.sh-Makes the script executable.

3.6. Access Control List (ACL) Commands

PlatformCommandDescriptionExample

3.7. Permission and Ownership Combination Examples

  • chown -R ali:admin proje/ - Changes ownership including subdirectories.
  • chmod 700 gizli.txt - Only the owner can access it.
  • setfacl -m u:veli:rw dosya.txt - Gives Veli read-write permission.
  • icacls dosya.txt /remove user - Removes access on Windows.

3.8. Parameters and Abbreviations

  • ls -l - View permissions
  • chown kullanıcı dosya - Change ownership
  • chmod +x script.sh - Make a script executable

Section summary: In this section you learnt how to manage file permissions and ownership with commands such as chmod, chown, icacls and setfacl. You can now manage file access safely.

7. Output redirection, logging and pipelines

Every command in the terminal produces output. That output can be printed to the screen, saved to a file or passed to another command. The system is built on the stdout (output), stderr (error) and stdin (input) streams.

7.1. Basic Operators

OperatorDescriptionExample
>Writes output to a file (overwrites it)ls > liste.txt
>>Appends to the end of the fileecho "Yeni" >> log.txt
2>Redirects error outputpython app.py 2> hata.txt
&>Redirects all outputcommand &> full.log

7.2. Using Pipes

  • ls | grep .txt - Filters for all .txt files.
  • ps aux | grep chrome - Finds a specific process.
  • dmesg | less - Shows output one page at a time.

7.3. Logging

  • command > log.txt - Saves the output.
  • command &> full.log - Logs both errors and output.
  • echo "$(date): işlem tamamlandı" >> app.log - Adds a timestamp.

7.4. Text Filtering and Processing

  • grep "error" log.txt - Find error lines.
  • sort dosya.txt - Sort lines.
  • wc -l - Count lines.
  • cut -d ":" -f1 - Take the first column.
  • awk '{print $1}' - Print the first column.
Section summary: You learned how to redirect command output (>, 2>), filter it (grep, awk) and keep logs.

9. Debugging, security and common errors

The terminal is powerful; a wrong command can have irreversible consequences. This section covers safe working practices and how to recognise and fix errors.

9.1. Dangerous Commands

  • rm -rf / - 🔥 Deletes the entire system.
  • chmod -R 777 / - 🚫 Gives everyone full access (dangerous).
  • dd if=/dev/zero of=/dev/sda - 💀 Wipes the disk.
Warning: Think twice before working with root privileges. A single wrong command can wipe the whole system.

9.2. Reading Command Errors

ErrorDescriptionSolution
command not foundThe command is not on the systemInstall it with the package manager (sudo apt install).
Permission deniedPermission errorAdd sudo or change the permissions (chmod +x).
No such file or directoryIncorrect file pathCheck the path.

9.3. Debugging Techniques

  • bash -x script.sh - Step-by-step tracing.
  • Set-PSDebug -Trace 1 - PowerShell script tracing.
  • echo $VAR - Show a variable's value.
  • set -e - Stop the script when an error occurs.

9.4. Log and Monitoring Files

  • /var/log/syslog - Linux system logs.
  • journalctl -p 3 -xe - Recent critical errors.
  • eventvwr.msc - Windows Event Viewer.

9.5. Writing Safe Scripts

  • Make a backup with cp before critical operations.
  • Use mv or trash instead of rm.
  • Quote your variables: "$VAR".
  • Add logging to scripts: echo "$(date): işlem yapıldı" >> script.log
Section summary: In this section you learned about dangerous commands, ways to resolve errors, safe use of sudo and error logging.
